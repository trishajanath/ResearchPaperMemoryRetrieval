============================================================
RQ2 -- SACR MATHEMATICAL ALIGNMENT EXPERIMENT
============================================================

## 1. Research Question

How can memory retrieval mathematically guarantee joint state and
contextual alignment?

## 2. Motivation

RQ1 showed that SACR's weighted ranking score,
  S_rank = 0.60*S_semantic + 0.25*S_context + 0.15*S_experience,
combined with a hard state-alignment threshold, sharply reduces
state-misaligned retrieval versus semantic-only retrieval. But a
weighted average, by itself, does not mathematically GUARANTEE any
particular alignment component stays above a bound -- a low S_state
or S_context can still be compensated by a high S_semantic. RQ2 asks
whether adding explicit hard eligibility constraints (rather than
relying on the weights alone) can make that guarantee structural.

## 3. Mathematical Formulation

S_state(q,m)   = (1/|S|) * sum_j sim(q_j, m_j),  j in STATE_COLS
S_context(q,m) = (1/|C|) * sum_j sim(q_j, m_j),  j in CONTEXT_COLS

Eligibility indicator:
  A(q,m) = 1  if S_state(q,m) >= tau_state AND S_context(q,m) >= tau_context
           0  otherwise

Only memories with A(q,m)=1 may enter the final retrieved set. Among
eligible memories, the existing (unchanged) ranking formula orders them:
  S_rank = 0.60*S_semantic + 0.25*S_context + 0.15*S_experience

Property tested, for every returned memory m of query q:
  m in R_k(q)  =>  S_state(q,m) >= tau_state  AND  S_context(q,m) >= tau_context

## 4. Existing SACR Limitation

Before RQ2, SACR enforced a hard threshold on S_state only
(tau_state = 0.7); S_context entered only the weighted
ranking score, so a memory with excellent context but poor state could
still be excluded by the state gate, but a memory with excellent state
and semantic similarity, yet poor context, faced no hard context
check at all -- only a 0.25-weighted contribution to its score, which a
high semantic or experience term could outweigh.

## 5. Proposed Eligibility Constraint

A second hard gate on S_context is added, opt-in via
`active_rules['min_context_alignment']`. RQ1's own `active_rules` dict
never sets this key, so RQ1's pipeline, results, and reports are
provably unaffected (verified by re-running RQ1's own demo script before
this experiment, with identical diagnostic counts).
The state threshold (0.70) and ranking weights are unchanged.

Selection rule (pre-committed, not chosen after seeing results): pick the
LARGEST candidate threshold for which every one of the 40 query instances
still has >= TOP_K (5) jointly state+context eligible candidates within
the top 100 semantic pool ('sufficient retrieval coverage', a hard
requirement); among values satisfying that, the largest is closest in
spirit to the existing 0.70 state threshold ('conceptual consistency') while
remaining as selective as the coverage requirement allows.

Chosen tau_context = 0.9
State threshold tau_state = 0.7 (unchanged from RQ1).

## 14. Interpretation

All four controlled tests passed, and the
exhaustive invariant check over all 40 real RQ1 query
instances found 0 joint violations out of 200 retrieved memories.
The comparison in Section 13 shows a state-violating memory whose naive
weighted score (0.999955) would have matched or beaten the actual top-5's lowest score (0.994532) under weighted-only ranking, yet the
eligibility gate rejected it outright -- illustrating why a weighted
average alone does not provide the structural guarantee an explicit gate does.

## 15. Limitations

- This verifies a STRUCTURAL property of the code (a row can only enter
  the ranked output after passing both checks), not a claim about clinical
  correctness, causal validity, or that tau_context/tau_state are optimal.
- Tests A-D use one fixed query (sacr.current_patient) and constructed
  (not organically retrieved) synthetic memories to guarantee the exact
  properties each test needs; they demonstrate the mechanism works as
  specified, not that it generalizes to every possible query/memory pair.
- tau_context was chosen from a small predefined candidate set using one
  coverage rule over the current 20 RQ1 scenarios; a different scenario
  sample or candidate set could select a different value.
- The chosen threshold's coverage margin is thin: the worst-case query
  instance had exactly 5 jointly-eligible candidates against
  TOP_K=5 -- a slightly different query or a smaller CANDIDATE_K could
  produce a query with fewer than TOP_K eligible memories at this threshold.
- This does not claim generalization to other datasets.

## 17. Conclusion

Under the similarity functions and thresholds defined above, adding an
explicit joint state+context eligibility gate to SACR structurally
prevents any memory violating either constraint from entering the final
retrieved set: 0 violations were found across
200 retrieved memories in the real RQ1 query scenarios,
and all four controlled tests behaved as the mathematical formulation
predicts. This is a narrow, code-level guarantee about this eligibility
mechanism under these similarity definitions -- it is not a claim of
clinical correctness, causal validity, or an optimal threshold choice.
