==============================================================================
RQ4 SEQUENTIAL SAMPLE-SIZE SENSITIVITY ANALYSIS
==============================================================================

*** THIS IS A FOLLOW-UP / DIAGNOSTIC ANALYSIS, NOT A REPLACEMENT OF RQ4 ***
The original RQ4 result (results/rq4/, 300 held-out queries) is preserved
unchanged and is NOT overwritten, rerun, or reinterpreted by this file. This
analysis exists only to diagnose why that 300-query evaluation saw almost no
OGMM activity, using the SAME frozen split, SAME frozen SACR mechanism, and
SAME frozen RQ3 governance parameters -- run at larger, nested query volumes.
results/rq1, results/rq2, and results/rq3 were verified byte-for-byte
unchanged before and after this run: True.

## 1. Motivation (recap)

Original RQ4 (300 queries): 0 quarantined, 2 downgraded, 1,354 distinct
memories touched across 1,374 retrievals (~1.01 retrievals/memory).
Standalone recurrence analysis (all 20,372 held-out encounters, pre-
governance): 93,067 retrievals, 50,191 distinct memories, 21.9% of distinct
memories retrieved >=3 times (RQ3's own N_MIN), max retrieval count 10.
300 queries is only 1.5% of that volume -- this analysis tests whether a
larger, sequential evaluation closes that gap.

## 2. Method (see full design documentation in this file's module docstring)

Checkpoints (queries): [300, 1000, 3000, 5000, 10000, 20372]
Sequence construction: np.random.default_rng(42).permutation(len(held_out_df)) over the full 20,372-row held-out set from experiments_rq4.build_split() (unmodified); prefixes [:N] of this single permutation are used for each checkpoint, guaranteeing nesting. Distinct from and does not call RQ4's own build_eval_queries() (a non-nested, fixed-size random sample).
Governance state (SG-QMS) and oracle bookkeeping (SACR shadow governance)
evolve SEQUENTIALLY and CUMULATIVELY across the single, nested query order;
each checkpoint N reports the state after processing exactly the first N
queries of that one deterministic sequence -- identical in principle to
restarting fresh with the first N encounters, computed in one pass for
efficiency. All governance functions (_new_governance_entry, _apply_feedback,
_update_quality, _meets_quarantine_criterion, _meets_downgrade_criterion,
_oracle_eligible_set, _effectiveness_and_false_rate) are imported directly
from experiments_rq3.py -- no governance logic was reimplemented.
Frozen params: N_MIN=3 BETA=-0.2 ALPHA=0.1 DOWNGRADE_THRESHOLD=0.4 state_threshold=0.7 context_threshold=0.9 lambda=(0.6,0.25,0.15) top_k=5 candidate_k=100
Pre-committed decision rules (fixed BEFORE running): 'meaningfully active' = >=5 distinct memories quarantined; 'unacceptable false quarantine' = false_quarantine_rate > 0.5. These thresholds were NOT chosen after seeing the results below, and N was never selected to maximize SG-QMS accuracy.

OGMM first becomes 'meaningfully active' (>= 5 quarantines, threshold fixed before this run) at N = 3000.
False-quarantine rate stayed at or below the pre-committed 50% unacceptability threshold at every evaluated N.

## 6. Limitations (carried over from RQ3/RQ4, plus new ones specific to this design)

- Outcome-proxy limitation (unchanged from RQ3/RQ4): `readmitted`-derived feedback
  is an experimental outcome proxy, not causal ground truth.
- SACR's shadow-governance oracle (used for false-quarantine-rate) reflects SACR's
  OWN unconstrained retrieval trajectory over this sequence -- as RQ3 itself notes,
  because SG-QMS's governance changes what it retrieves going forward, its
  trajectory can diverge from SACR's for reasons beyond the quarantine decision
  itself. This mirrors RQ3's own static-oracle caveat exactly, not a new gap.
- The nested full-sequence order (design note (a)) is a NEW, seed-42-based
  permutation distinct from RQ4's own build_eval_queries() sampling; it was
  necessary for nesting and is documented, not silently substituted.
- This is one deterministic query order; a different seed could shift exactly
  which memories reach N_MIN first, though the aggregate recurrence rate (from
  the separate, order-independent recurrence analysis) would not be expected to
  change materially.
- As in RQ4, majority-vote prediction is a simple, fixed, auditable rule, not
  claimed optimal; this experiment evaluates an outcome-proxy prediction task,
  not clinical validity or deployment safety.

## 8. Conclusion

This analysis reports where natural recurrence becomes large enough to expose
OGMM's governance mechanism at all, and separately whether that mechanism, once
exposed, changes downstream prediction behavior. It does not select or endorse a
final RQ4 evaluation size on the basis of maximizing any single outcome metric;
that choice is left to the accompanying human-written recommendation.
