## 1. Research Question

How does dynamic memory governance (SG-QMS = SACR + OGMM) improve downstream
task performance and retrieval safety compared with unguided SACR and
semantic-only baseline retrieval, when evaluated at a query volume large
enough for governance to actually be exposed to repeated memory retrieval?

## 2. Why the Original 300-Query Evaluation Was Insufficient for Governance

The original RQ4 run (results/rq4/, preserved unmodified) evaluated 300 held-out
queries and recorded 0 quarantines and 2 downgrades across 1,354 distinct
memories touched over 1,374 retrievals (~1.01 retrievals/memory). OGMM's
quarantine rule requires retrieval_count >= N_MIN=3 before a memory is even
eligible; at ~1.01 retrievals/memory, almost no memory could reach that bar.
This was not a defect in OGMM -- it was an evaluation-volume problem.

## 3. Sequential Recurrence Analysis (Summary)

A separate sample-size sensitivity sweep (results/rq4_sequential/, preserved
unmodified) ran the identical frozen SACR+OGMM mechanism across six nested
checkpoints (N=300 to 20,372) on one deterministic held-out query sequence.
Quarantine counts observed: N=300 -> 0, N=1,000 -> 1, N=3,000 -> 17, N=5,000 ->
49, N=10,000 -> 271, N=20,372 -> 1,168. The pre-committed criterion for
'meaningfully active' (>=5 quarantines, fixed before that sweep ran) is first
met at N=3,000.

## 4. Why N=3,000 Was Selected

N=3,000 was selected as the primary evaluation horizon because it is the first evaluated horizon at which OGMM reaches the pre-committed meaningful-activity criterion of at least 5 quarantinations. This is a methodological evaluation-horizon choice, not a claim that 3,000 is optimal.
This evaluation horizon was read off the sequential sweep's own pre-registered
decision rule, not chosen after comparing accuracy across candidate N values.

## 7. Exact Evaluation Protocol

Query stream: the FIRST 3,000 rows of a single, full-length, seed-42
permutation of all 20,372 held-out rows (identical construction to results/rq4_sequential/,
re-verified below to produce numerically identical N=3,000 statistics). All three
conditions process this exact same ordered 3,000-query sequence. Governance state (SG-QMS)
and SACR's own oracle bookkeeping evolve cumulatively across the sequence -- each query is
predicted BEFORE that query's own true label is used for anything, and governance updates
use only the RETRIEVED memories' own historical feedback, never the current query's label.

## 16. Limitations

- Outcome-proxy limitation (unchanged from RQ3/RQ4): `readmitted`-derived feedback is an
  experimental outcome proxy, not causal ground truth or a clinical validity claim.
- N=3,000 is a governance-EXPOSURE threshold, not an accuracy-optimizing choice; the
  sequential sweep (Section 3) shows recurrence and governance activity both keep growing
  well past N=3,000 -- this evaluation deliberately does not claim 3,000 is where the system
  performs best, only where OGMM first has enough to work with by the pre-committed rule.
- SACR's shadow-governance oracle (false-quarantine-rate denominator) reflects SACR's own
  unconstrained trajectory over this sequence; SG-QMS's governance changes what IT retrieves
  going forward, so its trajectory can diverge from SACR's for reasons beyond the quarantine
  decision itself (the same caveat RQ3 documents for its own static oracle).
- Single deterministic seed/order (42); a different ordering could shift which specific
  memories reach N_MIN first, though the sequential sweep's aggregate recurrence rate is
  order-independent evidence that this is not a seed-specific artifact.
- Majority-vote prediction is a simple, fixed, auditable rule, not claimed optimal.
